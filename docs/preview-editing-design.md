# プレビュー編集 (direct manipulation) — 設計 & ロードマップ

2026-07-17〜18 の設計会話の成果物。project-files-design.md と同じ流儀で、
決定事項 → 技術メモ → フェーズ分けロードマップの順。

3D プレビューを「閲覧装置」から「編集装置」へ広げる。土台は選択ギズモ
(2e1a0ed: ピボット/ソケット/枠 + 表示トグル)とクリック選択 (93e12f0)。
インスペクタの数値編集は今後も残る — gizmo で書けない自由値・微値の逃げ道。

## 1. スコープ

- **移動・回転**をプレビュー上の gizmo でドラッグ編集。対象は3種:
  パーツ本体(manifest の position/rotation)、ピボット(pivot.pos)、
  ソケット(socket.pos / socket.rot)
- **ボクセルの追加・削除・ペイント**をプレビュー上のクリック/ドラッグで

## 2. 決定事項

### 2.1 モードモデル — ツールモード方式(Blender / MagicaVoxel 型)

プレビュー常設のツールバーで明示的にツールを切り替える:

```
[選択] [移動] [回転] │ [追加] [削除] [塗り]
```

- 既定は「選択」— 現状のクリック選択・視点操作がそのまま。**選択ツール中は
  何をしても model が壊れない**、が最重要の保証
- ビューで意味をなさないツールはグレーアウト(tooltip で理由。view-toggle の
  disabled と同じ流儀)
- 却下した代替案: 選択駆動(Unity 型、選択で即 gizmo)はうっかりドラッグ事故
  と「ボクセル用モードが結局別に要る」二本立てが難点。ハイブリッドは状態の
  組み合わせが最多で学習コスト大

### 2.2 ビュー × 編集の対応表

| 編集対象 | Cvox | Rig | Anim |
|---|---|---|---|
| ボクセル 追加/削除/塗り | ○ | ○ | ○(一時停止中) |
| パーツ position/rotation | —(意味なし) | ○ | —(将来: キーフレーム編集) |
| ピボット 移動 | ○ | ○(補正付き §2.3) | — |
| ピボット 回転(pivot.rot) | ○(軸クロスが pivot.rot を表示・回る) | ○(パーツごと回る) | — |
| ソケット 移動/回転 | ○(軸が world と一致) | ○(パーツローカル軸) | — |

- ボクセル編集はどのビューでも同一コードパス(ヒットを逆行列でパーツローカル
  ボクセル座標に落とす)なので全ビュー対応がタダで付く
- **Anim ビューの transform 編集は v1 対象外**。Anim の表示位置は
  rest + アニメサンプルの合成なので、gizmo ドラッグが「何を書くか」が曖昧
  (rest? キーフレーム?)。「gizmo でキーフレームを打つ」は将来の別企画として
  切り出す(§5)

### 2.3 ピボット移動は常に補正付き

ピボットは「回転の支点をどこに置くか」の編集であって「パーツをどこに置くか」
の編集ではない。この役割分離をそのまま挙動にする:

- pivot.pos の編集と同時に manifest の position を逆補正
  (`position += q · Δpivot`、q はパーツの rest 回転)し、
  **パーツの見た目位置を不変に保つ**。マーカーだけが動く
- 親の position が動くと子パーツがズレるので、**子パーツの position にも
  逆補正**を同じ編集に畳む
- cvox(pivot)+ manifest(position ×N)の複数ファイル編集を **1 dispatchEdit
  = 1 undo** で(rename/delete が既にやっている流儀)
- 不変条件: **ピボット編集はレンダリング結果を変えない**。Cvox ビューで
  動かして Rig ビューに切り替えても位置がズレない
- manifest エントリが無いパーツ(rig 未配置)は補正相手がいないので素の編集
- **pivot.rot も gizmo で編集可**(実装時に改訂: 当初は「manifest.rotation と
  見た目が区別できず書き先が曖昧」として見送ったが、ピボットのモードトグル
  (§2.4)が書き先を明示するので曖昧さは消えた)。回転ツール+ピボットモード=
  pivot.rot、パーツモード= manifest.rotation。gizmo はどちらもパーツの
  rig グループにアタッチし(ライブプレビュー共通)、コミット時に §7.7 の合成
  q_rotation ⊗ q_pivot から編集対象でない側を割り戻す(パーツ編集は右から
  q_pivot、ピボット編集は左から q_rotation)。ピボット回転は補正なし
  (ジオメトリの向き自体の編集なので見た目も回る)。Cvox ビューでは
  ピボットマーカーの軸クロス自体を pivot.rot で回して表示し、それが
  ライブプレビューになる(world 座標 = パーツ座標なのでマーカーの
  クォータニオンをそのまま格納)

### 2.4 移動/回転の対象指定 — クリックで決める

移動・回転ツール中: パーツ本体をクリック=パーツが対象、ピボット/ソケットの
マーカークリック=**モードトグル**(同じマーカーを再クリックでパーツ対象に
戻る)。対象に gizmo(drei TransformControls)が付き、移動は**矢印(1軸)と
平面ハンドルのみ**(実装時に改訂: 中央の自由移動ハンドルは「マーカー自体を
掴んでいるように見える」ため削除)。マーカーは見た目より大きい不可視球で
掴め、レイ上にマーカーがあればパーツ本体はクリックを譲る(マーカーは
メッシュ内部にあることが多く、素の距離順ではパーツ表面が先に食うため)。

### 2.5 スナップ — 既定オン + Shift で細刻み

| 対象 | 既定 | Shift |
|---|---|---|
| パーツ移動 | 1.0 | 0.1 |
| ピボット・ソケット移動 | 0.5 | 0.1 |
| 回転(全対象) | 15° | 1° |

ドラッグでは自由値を書けない(ファイルに端数を混入させない)。自由値が
必要ならインスペクタの数値入力で。

### 2.6 ボクセルツールの操作系

- 対象は**選択中のパーツのみ**。他パーツへのクリックは無反応(誤編集防止。
  パーツを替えるには選択ツールに戻る)
- 追加・塗りの色は**パレットパネルで選択中の色**
- クリック=1ボクセル、**ドラッグ=ストローク連続編集**(なぞって連続
  追加/削除/塗り)。ストローク1本 = 1 undo
- 追加のセマンティクス: 既存ボクセルの面をクリック → その面の隣に1個。
  ドラッグ中の当たり判定は**ストローク開始時のジオメトリのスナップショット
  のみ**(表示メッシュと置いたばかりのボクセルはレイキャスト対象外)。
  置いた出力を自分でヒットできないので、なぞりは元の表面に沿って必ず
  1層で止まる(実装時に改訂: 当初の「開始面の平面ロック」はロック軸と
  違う向きの面を経由してカメラ側へ増殖する穴があり、スナップショット
  方式に置換 — 削除ツールの層掘り防止と同じ仕組みに統一)
- **Alt + ドラッグ = 視点回転。全ツールで常に有効**(「困ったら Alt+ドラッグ
  すれば必ずカメラ」の一貫した逃げ道)。選択/移動/回転ツール中は素の
  左ドラッグも従来通り回転。ボクセルツール中のみ素の左ドラッグが編集になる。
  ホイールズーム・中/右ドラッグ(パン)は全ツール不変
- 修飾キーの将来枠: Space = アニメ再生/停止、Ctrl+クリック = クイック削除系
  (どちらも今回は未実装、Alt を専有しない理由づけとして記録)

### 2.7 追加によるグリッド拡張

パーツのボクセルは w×h×d の固定グリッド(§7)。箱の外側への追加は
(実装時に詳細化):

- **ストローク中はグリッドを触らない**。枠外セルはゴーストキューブとして
  プレビューし、**コミット時に一度だけ**グリッドを拡張して voxels 配列を
  作り直す — 1 undo。ストローク中に再拡張すると座標系がドラッグの足元で
  ズレるため
- 負方向への拡張は原点がズレるので **pivot.pos と全 socket.pos を同じ量だけ
  平行移動**する。manifest の補正は**不要** — 描画は v−pivot なので、
  ボクセルとピボットが一緒にズレれば正確に相殺される(当初の想定を訂正)。
  Rig ビューは何も動かない。生座標を描く Cvox ビューだけはコミット時に
  一度だけ原点が付け替わる
- 削除で外周が空いても自動シュリンクはしない(暗黙のデータ変形は事故の元。
  シュリンクは将来インスペクタの明示操作として検討)

## 3. 技術メモ

- **gizmo**: drei `TransformControls`(translate / rotate モード)。
  `OrbitControls makeDefault` との共存はドラッグ中自動無効の解決済み
  パターン。スナップは `translationSnap` / `rotationSnap` にそのまま渡せる
- **undo**: ドラッグ中はローカル state でプレビューのみ更新し、pointer-up で
  `dispatchEdit` 1発 = 1 undo として確定(タイムラインのマーカードラッグと
  同じ流儀)。ドラッグ中の連続 dispatch は履歴を汚すので不可
- **ボクセルヒット判定**: raycast の hit point + face normal をパーツの
  逆ワールド行列でローカルに落とし、`floor` でボクセル座標へ。追加は
  normal 側に +1。全ビュー共通
- **ボクセル編集の書き込み**: 対象パーツの定義ファイル(merged.files)の
  AST を `mapGeometryFiles` で書き換え → serialize。既存の構造編集と同経路
- **ツール状態**: App の `useState`(gizmoVis と同格の viewer preference)。
  ビュー切替で使えないツールになったら「選択」へフォールバック

## 4. ロードマップ

各フェーズ = 実装 → アプリで動作確認 → OK → コミット。

- **P1 — ツールバー骨格 + パーツ移動(Rig)**: ツールバー UI(6ツール、
  無効化ロジック込み)+ 移動ツールでパーツ本体の TransformControls →
  manifest position 書き込み。gizmo → undo → serialize の縦一本を最小で通す
- **P2 — パーツ回転(Rig)**: 回転ツール + manifest rotation 書き込み。
  15°/1° スナップ
- **P3 — ピボット/ソケットの移動・回転**: マーカーのクリック対象化、
  補正付きピボット移動(§2.3)、ソケット移動/回転。Cvox + Rig 両ビュー
- **P4 — ボクセル削除・塗り**: ヒット→ボクセル座標変換、クリック +
  ストローク編集。グリッドサイズ不変なので追加より先
- **P5 — ボクセル追加**: 面クリック追加、平面ロックストローク、
  グリッド拡張(§2.7)
- **P6 — 磨き**: ツールショートカット(V/G/R/B 系)、ホバーハイライト
  (削除・塗り対象のプレビュー)、ドラッグ中の座標 HUD、など使ってみて
  効くものから
